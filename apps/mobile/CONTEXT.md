# Radio Context

The AI radio experience. The user does not build playlists or search for tracks — they choose a Channel and the AI Host takes over. The Host pre-generates a Programme of Tracks and Interludes. When the user intervenes (点歌, mood change, voice/text instruction), the Host generates a new Programme.

## Language

### Channels

**Channel**:
A named, preset radio station with a defined style (e.g. "深夜电台", "晨间咖啡", "专注工作"). Channels are app-defined, not user-created. A Channel provides the style context the Host uses to build a Programme.
_Avoid_: playlist, station, mode

**Channel Style**:
The rules and preferences that define a Channel — genre hints, energy level, tempo range, mood. Used by the Host to filter the Library into a CandidateSet, and to guide Interlude tone.
_Avoid_: theme, vibe, genre

### The AI Host

**Host**:
The AI DJ for a Channel. The Host queries the Library for a CandidateSet, selects and sequences Tracks, writes Interlude Scripts, and assembles a Programme. The Host runs at Programme-generation time, not in real-time during playback.
_Avoid_: AI, model, recommender, algorithm

**Programme**:
A pre-generated, ordered sequence of Segments (Tracks and Interludes) produced by the Host for a Channel. The Player consumes a Programme sequentially. A Programme is replaced when it is nearly exhausted or when an Intervention occurs.
_Avoid_: queue, playlist, set, episode

**Interlude**:
A short spoken segment generated by the Host and synthesised via cloud TTS, inserted between Tracks in a Programme. An Interlude is a playable audio Segment with a URL — the Player treats it identically to a Track.
_Avoid_: announcement, narration, transition, jingle

**Interlude Script**:
The text the Host writes for an Interlude before TTS synthesis. Ephemeral — discarded after the audio URL is returned.
_Avoid_: prompt, message, text

### User Interaction

**Intervention**:
A user action that causes the Host to discard the current Programme and generate a new one. Three types: **Track Request** (点歌), **Mood Change** (调整风格/情绪), **Free Instruction** (语音或文字自由表达).
_Avoid_: user input, command, request (when meaning the regeneration trigger)

**Track Request**:
An Intervention where the user names a specific Track to play. The Host generates a new Programme that honours the request at an appropriate position while preserving Channel flow.
_Avoid_: song request, play next, queue insert

**Mood Change**:
An Intervention where the user shifts the Channel Style without switching Channels (e.g. "更轻松一点", "节奏快一些"). The Host generates a new Programme under the adjusted style.
_Avoid_: vibe change, filter change

**Free Instruction**:
An Intervention expressed as natural language voice or text (e.g. "来点雨天适合听的"). The Host interprets it and generates a new Programme.
_Avoid_: voice command, chat, query

### Selection

**CandidateSet**:
The subset of the Library matching the current Channel Style, produced by rule-based filtering. The Host selects and sequences from the CandidateSet — it never operates on the full Library directly.
_Avoid_: filtered list, recommendations, search results

## Relationships

- A **Channel** has exactly one **Channel Style**
- The **Host** consumes a **Channel Style** to produce a **CandidateSet**, then sequences it into a **Programme**
- A **Programme** contains Tracks and **Interludes** interleaved by the Host
- An **Intervention** causes the **Host** to produce a replacement **Programme**
- A **Track Request**, **Mood Change**, and **Free Instruction** are all subtypes of **Intervention**

## Example dialogue

> **Dev:** "When the user says '来首周杰伦', do we insert the track into the Programme mid-playback?"
> **Domain expert:** "No — that's a Track Request, which is an Intervention. The Host generates a new Programme. The new Programme will include the requested track at a natural position. The Player switches to the new Programme."
> **Dev:** "Does the user see the Programme — like a tracklist of what's coming?"
> **Domain expert:** "No. They see Now Playing only. The Programme is the Host's internal plan, not a user-facing list."

## Dual Mode Coexistence

Radio mode is the primary experience, but Classic (queue-based) playback coexists (see ADR 0006):

- Users can exit radio by manually selecting a track from the Library → enters Classic mode
- Classic mode retains full queue control (add, insert next, shuffle, reorder)
- This is especially important offline where the AI Host is unavailable
- Only one mode is active at a time; switching is implicit

## Flagged ambiguities

- "Radio" is used colloquially to describe the whole product, but the domain term for what the user tunes into is **Channel**. "Radio" does not appear in code.
- "Queue" in Classic mode is the traditional user-managed concept. "Programme" in Radio mode is Host-generated and opaque. Both exist — "Queue" is not deprecated, it is scoped to Classic mode.
