# Radio Context

The AI radio experience. The user does not build playlists or search for tracks — they choose a Channel and the AI Host takes over. The Host pre-generates a Programme of Tracks and Interludes. When the user intervenes (点歌, mood change, text instruction), the Host generates a new Programme.

## Language

### Channels

**Channel**:
A named, preset radio station with a defined style (e.g. "深夜电台", "晨间咖啡", "专注工作"). Channels are app-defined, not user-created. A Channel provides the style context the Host uses to build a Programme.
_Avoid_: playlist, station, mode

**Channel Style**:
The rules and preferences that define a Channel — genre hints, energy level, tempo range, mood. Used by Library filtering to produce a CandidateSet, and by the Host to guide sequencing and Interlude tone.
_Avoid_: theme, vibe, genre

### The AI Host

**Host**:
The AI DJ for a Channel. The Host receives a CandidateSet, selects and sequences Tracks, writes Interlude Scripts, and produces a Programme. The Host runs at Programme-generation time, not in real-time during playback.
_Avoid_: AI, model, recommender, algorithm, agent

**Host Policy**:
The app-owned, versioned rules that govern every Host generation, including its role, Programme constraints, and output boundaries. Channel data customises a generation but cannot override the Host Policy.
_Avoid_: system prompt, master prompt, agent instructions

**Host Voice**:
The app-defined, provider-independent voice identity assigned to a Channel. It is mapped to a provider-specific TTS voice by an adapter and is not user-selectable in V1.
_Avoid_: voice ID, TTS voice, speaker setting

**Programme**:
A pre-generated, ordered sequence of Segments (Tracks and Interludes) produced by the Host for a Channel, targeting 30–45 minutes of playback rather than a fixed Track count. The Player consumes a Programme sequentially. A Programme is replaced when it is nearly exhausted or when an Intervention occurs.
_Avoid_: queue, playlist, set, episode

**Programme Manager**:
The coordinator for a Channel session. It queries the Library for a CandidateSet, asks the Host for Programmes, loads Programmes into the Player Store, pre-generates the next Programme near exhaustion, and applies Interventions at a Segment boundary.
_Avoid_: player, queue manager, scheduler

**Session Context**:
The bounded, temporary context for one Channel session that the Programme Manager supplies to the Host, including Track recency, the effective Channel Style, and the current Intervention when present. It is discarded when the Channel session ends.
_Avoid_: memory, chat history, agent state

**Interlude**:
A short spoken segment generated by the Host and synthesised via cloud TTS, inserted before a Track within the cadence allowed by the Host Policy. While an Interlude plays, the following Track starts underneath it at a ducked volume; the music continues and returns to normal volume when the Host finishes.
_Avoid_: announcement, narration, transition, jingle

**Interlude Script**:
The text the Host writes for an Interlude before TTS synthesis. Ephemeral — discarded after synthesis succeeds.
_Avoid_: prompt, message, text

### User Interaction

**Intervention**:
A user action that causes the Host to discard the current Programme and generate a new one. Three types: **Track Request** (点歌), **Mood Change** (调整风格/情绪), **Free Instruction** (V1 uses text input).
_Avoid_: user input, command, request (when meaning the regeneration trigger)

**Track Request**:
An Intervention where the user names a specific Track to play. The current Segment finishes, then the replacement Programme may begin with a short acknowledgement Interlude and must use the requested Track as its first Track.
_Avoid_: song request, play next, queue insert

**Mood Change**:
An Intervention where the user shifts the Channel Style without switching Channels (e.g. "更轻松一点", "节奏快一些"). The Host generates a new Programme under the adjusted style.
_Avoid_: vibe change, filter change

**Free Instruction**:
An Intervention expressed as natural-language text about the desired Programme (e.g. "来点雨天适合听的"). The Host interprets it and generates a new Programme. It cannot control volume, pause, or Track skipping in V1; voice input is outside V1 scope.
_Avoid_: voice command, chat, query

### Selection

**CandidateSet**:
The subset of the Library matching the current Channel Style, produced by rule-based filtering. The Host selects and sequences from the CandidateSet — it never operates on the full Library directly.
_Avoid_: filtered list, recommendations, search results

## Relationships

- A **Channel** has exactly one **Channel Style**
- A **Channel** has exactly one **Host Voice**
- Every **Host** generation follows the current **Host Policy**
- The **Programme Manager** loads a **Channel**, asks the Library for a **CandidateSet**, and supplies it with the **Session Context** to the **Host** to produce a **Programme**
- A **Programme** contains Tracks and **Interludes** interleaved by the Host
- An **Intervention** causes the **Host** to produce a replacement **Programme**
- A **Track Request**, **Mood Change**, and **Free Instruction** are all subtypes of **Intervention**

## Example dialogue

> **Dev:** "When the user says '来首周杰伦', do we insert the track into the Programme mid-playback?"
> **Domain expert:** "No — that's a Track Request, which is an Intervention. The current Segment finishes, then the Player switches to the replacement Programme. After an optional acknowledgement, the requested Track is the first Track."
> **Dev:** "Does the user see the Programme — like a tracklist of what's coming?"
> **Domain expert:** "No. They see Now Playing only. The Programme is the Host's internal plan, not a user-facing list."

## Dual Mode Coexistence

Radio mode is the primary experience, but Classic (queue-based) playback coexists (see [ADR 0002](../../docs/adr/0002-dual-playback-modes.md)):

- Users can exit radio by manually selecting a track from the Library → enters Classic mode
- Classic mode retains full queue control (add, insert next, shuffle, reorder)
- This is especially important offline where the AI Host is unavailable
- Only one mode is active at a time; switching is implicit

## Flagged ambiguities

- "Radio" is used colloquially to describe the whole product, but the domain term for what the user tunes into is **Channel**. "Radio" does not appear in code.
- "Queue" in Classic mode is the traditional user-managed concept. "Programme" in Radio mode is Host-generated and opaque. Both exist — "Queue" is not deprecated, it is scoped to Classic mode.
- "Agent" was used as a second name for the **Host** — resolved: **Host** remains the canonical domain term; agent describes an implementation style, not a separate domain concept.
- "Memory" was used for playback continuity — resolved: V1 uses bounded **Session Context** and has no persistent user memory or model-owned conversation state.
- Natural-language player commands were considered part of the **Host** — resolved: V1 **Free Instructions** only guide Programme generation; playback controls remain deterministic Player operations.
- "Free Instruction" previously included voice and text — resolved: V1 accepts text only; speech-to-text is a later input capability, separate from the Host generation flow.
